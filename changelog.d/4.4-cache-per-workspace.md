### Added
- `[cache] max_size_mb` (default 2048): per-workspace quota of the persistent parse cache,
  database + WAL. Checked on open and after every scan batch writing more than 100 entries (or
  leaving the files over quota); over quota, least recently used entries are evicted in batches
  of 1,000 down to 80 % of it, then `PRAGMA incremental_vacuum`.
- `PersistentIndexCache::stats()`: hits, misses, swallowed SQLite errors, evicted entries.
- `scripts/bench/cache_growth.py`: simulated work week (30 branch switches, 10 rebases, one cold
  boot after each) measuring cache size per entry and growth, with an isolated `HOME`.

### Changed
- The parse cache is one SQLite file per workspace,
  `~/.cache/mesh-mcp/workspaces/<workspace_id>/index-cache.db` (same `workspace_id` as the
  daemon socket), created with `auto_vacuum = INCREMENTAL`; cache schema version 4. The old
  machine-wide `~/.cache/mesh-mcp/index-cache.db` is no longer read (safe to delete).
- Incremental reloads now read and write the cache (a branch switch back to already-seen content
  is a lookup, not a re-parse), and record `last_accessed_at` in batch, never per read.

### Fixed
- The parse cache no longer grows without bound: it had no eviction and was shared by every
  workspace on the machine.
