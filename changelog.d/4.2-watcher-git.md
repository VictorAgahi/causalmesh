### Changed
- macOS file watching no longer falls back to polling on workspaces with more than 200 directories. Each configured root is watched by one recursive FSEvents stream, and `.gitignore`/`exclude_patterns` are applied in memory to every event. `PollWatcher` is only used for a root FSEvents refuses to watch (network or unsupported volume), with an explicit `warn`. Linux and Windows keep per-directory watches. On a 503-directory workspace, idle `meshd` CPU went from polling to event-driven (figures in `docs/quality.md`).

### Fixed
- A reload no longer runs in the middle of a Git operation. For each root, the watcher resolves the real Git directory, following `gitdir:` when `.git` is a file (submodule, `git worktree`). It holds changed paths while `index.lock`, `rebase-merge/` or `rebase-apply/` exists or `HEAD` is moving, then reloads everything once, as a single generation, when the operation has settled. A hold lasts at most 60 s. An `index.lock` older than 30 s with no `git` process of the user (`pgrep`, falling back to `ps`) is treated as orphaned, with a `warn`. While a hold is open, tool results still answer immediately from the last complete snapshot and start with a note naming its generation. Previously, a `git checkout` of 3,000 files installed partial generations mixing both branches (`scripts/test_git_storm.sh`).
- On macOS (and the polling fallback), a directory renamed or moved into a watched root is reindexed: its event is no longer discarded by the file-extension filter, and triggers a full reload, which also forgets the files under the old name.

### Added
- `scripts/test_git_storm.sh`: checks out 3,000 rewritten files while `smart_search` runs in a loop, and checks that no generation is installed during the checkout, exactly one after it, and that its fingerprint matches a cold index of the same directory.
