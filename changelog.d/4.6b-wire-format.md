### Added
- `analyze_grpc` checks the `.proto` that defines the target for wire-format breaking changes
  against a Git base, each reported as `WIRE_FORMAT_BREAKING_CHANGE`: a field number reused for
  another field (or a number `reserved` in the base used again), an incompatible type or
  cardinality change (compatibility table in `docs/mcp-tools.md`), and a field deleted without
  `reserved` (number, range, `to max`, or name). Handles `oneof`, `map<>`, nested messages.
- New optional `base` argument. Default: `git merge-base HEAD <ref>` for the first existing of
  `origin/HEAD`, `origin/main`, `main`, else `HEAD`; never `HEAD~1`. The report names the ref and
  commit used. A `.proto` path passed as `target` is checked directly.
- The base version is read in memory (`git show --no-textconv <sha>:<path>`): no shell, one argv
  entry per argument, `base` starting with `-` or containing `:` refused before `git` runs,
  `--end-of-options`, 5 s timeout per command, `GIT_DIR`-style variables removed, and both versions
  behind the indexing parser guard. File absent from the base → "new file"; with an explicit
  `base`, no repository, unknown base or no `git` on the `PATH` → `isError`; without `base`, those
  environment failures become a one-line note so the trace stays usable outside Git checkouts.
