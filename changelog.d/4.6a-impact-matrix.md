### Changed
- `analyze_impact` returns an **impact matrix**: a compact Markdown table with one row per impacted
  element — gRPC handlers and clients of a proto method or service (resolved through the same
  `Implements` / `CallsRpc` edges as `analyze_grpc`, previously out of scope for this tool), plus
  the async producers, topics, consumers and sagas it already reported. Each row is `EXTERNAL`
  (another workspace root than the contract owner's) or `INTERNAL` (same root) and carries its edge
  confidence (`exact` / `heuristic` / `ambiguous`). Owner = roots of the implementing handlers,
  else the `.proto` root (events: producers' roots, else topics'). Ambiguous fan-out gives one row
  per candidate contract; a service-level client is capped at `heuristic`; rows are deduplicated
  per `(element, role, via)` and totally ordered. Rules in `docs/mcp-tools.md`. No test-coverage
  category.

### Added
- `analyze_impact` optional `limit` (default 100, max 200) and `offset` arguments: pages follow the
  `smart_search` rules (48 KB budget, exact next `offset` in the footer).
- `examples/polyglot-shop`: the Go payment worker registers `PaymentService` and opens an
  `InventoryService` client; the Rust inventory manager implements `InventoryService` tonic-style —
  so the fixture exercises Go and Rust gRPC servers and clients, not only their languages.

### Fixed
- `analyze_impact` `depth > 1` never reached a consumer on an indexed workspace: the traversal only
  followed `Consumes` edges as consumer → topic, while `reconcile_edges` emits them topic →
  consumer. It now takes the newly discovered topic end of a `Consumes` edge, whichever direction
  it was built in. Known limit: a pattern-declared consumer (`consume:` node) and producer
  (`produce:` node) of the same service are distinct nodes, so a hop through such a service is
  still not followed.
