### Security
- `meshd` now confines itself on Linux right after binding its socket: a seccomp filter, installed on every thread with `SECCOMP_FILTER_FLAG_TSYNC` plus `PR_SET_NO_NEW_PRIVS`, makes `socket(AF_INET/AF_INET6)` and `io_uring_setup` fail with `EPERM`, so the daemon cannot open any network connection. `AF_UNIX` is unaffected. If the kernel refuses the filter, `meshd` logs a warning and keeps serving; set `MESH_DAEMON_SANDBOX=required` to make it exit instead. Only `meshd` is confined (not `mesh-mcp run` nor `mesh-mcp graph --open`); macOS and Windows are unchanged. See `docs/architecture.md` §8.3. Any other non-empty `MESH_DAEMON_SANDBOX` value is logged and treated as `required`; on Windows, `required` makes `meshd` refuse to start. `mesh-mcp doctor` reports on Linux whether the running `meshd` is confined.
