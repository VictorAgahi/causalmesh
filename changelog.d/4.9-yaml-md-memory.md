### Added
- `scripts/bench/gen_yaml_md_corpus.py` + `scripts/bench/yaml_md_peak.py`: a deterministic YAML/Markdown corpus sized at the per-file caps, and a per-file peak-memory measurement (`/usr/bin/time -l` peak footprint, parser delta via the `parse_peak` example plus whole-process delta via `graph --format fingerprint`, median of 3). The results are in `docs/quality.md` (step 4.9).

### Changed
- YAML is now streamed event by event (`mesh_core::yaml_stream`, driving libyaml via `unsafe-libyaml`) instead of `serde_yaml` 0.9 buffering a whole document's event list. The parser's own memory on a 1.5 MB OpenAPI/AsyncAPI spec drops from 24–29x the file size to 2.2x (OpenAPI 42.9 MB to 3.4 MB). Extracted properties and contracts are identical on the 376 YAML files of the golden corpora.
- Markdown sections are split line by line under an explicit per-file budget (estimated resident bytes at most 3x the file). Past the budget, later headings no longer open new sections, and the rest of the file stays searchable in the last section. Sections share one path allocation per file, and prompt-injection sanitising no longer copies the whole file. A 384 KB file with 6,244 short sections drops from 8.3x to 2.9x.

### Fixed
- Security: YAML alias fan-out could exhaust memory. `serde_yaml`'s alias guard counts alias jumps, not replayed nodes, so one large anchor replayed by many aliases got past it: a 30 KB `openapi.yaml` pushed indexing to 1.85 GB, and a 1.5 MB one was killed at 2 GB. Anchor recording and alias replay are now charged to a per-file budget (1 event per input byte, minimum 64 Ki), and flattened Spring properties to a per-file output budget (8x the input, minimum 64 KB). A file over either budget ingests nothing. The same 30 KB file now peaks at 3.0 MB and the 1.5 MB one at 106 MB.
